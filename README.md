## Introduction
This project consists of a (static) demo of the 5ARF0 Ethics of AI: theory and practice course from TU Eindhoven. The subject of interest is AI for Eating Disorder Symptoms. The goal is to create a product on top of an existing product like Featback to explore what role AI might play in assisting users. More information can be found in docs/AssignmentDescription.txt.


## Instructions
You are instructed to bring a concrete example (mock-up or demo) of one of the (intended) outputs of the designed tool in its intended function: for example, a sample chat generated by a chatbot; a sample decision made by an animal-management AI tool; or sample guidance provided by an AI-based environmental impact tool. You should also make clear how this is intended to respond to feedback from users.
You will show the example during the session, either on paper or on a screen. 
You can write or compose it yourself or by an alternative method. But it should be intended seriously as a model for what the output will (or should) look like.

In addition, you should be able to explain your progress in specifying the following additional elements:
The intended interface(s) with the users. Where and how will the tool be available?
The evaluation metrics you might use for the (intended) outputs. How can you determine the quality of the outputs within a test context or a context of interaction?


## Running the demo
```
npm install
npm run dev      # then open the printed localhost URL
npm run build    # static build in dist/
```

The app is fully static: scripted conversations, no real AI, no data leaves the browser.

- **Use cases**: seven scripted conversations in a phone mock-up. The right panel shows which requirement from the Phase 1 draft each step implements, and a log of how the AI responded to the user's feedback. Two personas (Sam, an existing user, and Noor, a new user) keep their data across use cases, so a correction in one carries over to the next.
- **Interfaces**: where the tool is available and who can see what.
- **Evaluation**: metrics per output in a test context and an interaction context, plus a per-subgroup fairness example.
- **Design basis**: the personalisation cycle, the value-based requirements, constraints and open questions.

Scripts live in `src/data/scenarios.ts`, the approved strategy library in `src/data/strategies.ts`, and the (transparent, rule-based) pattern, ranking and safety logic in `src/logic/engine.ts`.
